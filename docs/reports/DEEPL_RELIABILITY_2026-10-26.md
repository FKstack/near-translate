# DeepL 连续可靠性修复与未通过的验收

2026-10-26。**本轮尚未达到“连续多篇完整翻译、同时保持15秒多”的要求，未正式发布。** 候选 C 的首轮 Go 长文完整耗时14.8363秒，但连续到第十篇时仍收到真实HTTP429。不得用首轮成功、单元测试或版本号代替稳定性验收。

结构化计时、逐请求数字与原始文件哈希见[本轮证据](../evidence/deepl-reliability-2026-10-26.json)。公开发行仍为v0.11.16；0.11.17仅为本地候选版本，同版本候选A/B/C须用SHA256区分。

## 已确认的问题与修复

用户的场景是同一篇文章停止后立即重试。截图里的倒计时本身不能证明本次刚发生HTTP429：它也可能来自已保存的共享保护状态；普通NETWORK/TIMEOUT不会自行创建限流冷却。现在只把真实上游HTTP429或明确的JSON限制响应标为上游诊断，并透传安全枚举、状态码、时间和有效Retry-After，不向页面公开正文、Key、Cookie或任意服务器错误文本。

本轮查到两个独立的客户端缺口：篡改猴每个文档新建调度器，未继承上一页的短时启动记录；共享冷却的read-max-write也可能被并发短期限覆盖。A真实连续测试中，各文档自身均未用满30次预算，合在一起却达37次/12秒。

已实现的保护如下：

- 篡改猴用每次启动的独立不可变记录继承已可见的跨文档历史，取消不退款、不按相同毫秒去重；先记录再执行，读写故障清队并取消已有任务。GC保留时钟锚，回拨不会靠丢弃旧记录重新获得预算。GM缓存是最终可见状态，**不是原子全局锁**。
- 共享限流和恢复确认证据采用不可变最大值记录，较短观察不能覆盖较长冷却。恢复确认只覆盖其捕获的旧期限，不能抹去更新的受限记录。
- 真正受限或已有I/O被用户取消后，先只放行一个真实未完成批次；完整有效成功才恢复并发。失败停止整个本次尝试，不自动轮流把等待批次变成新探测，不新增样本请求。遇429尊重有效Retry-After，并保留至少60秒保护和同实例连续失败退避。
- 候选 C 的篡改猴策略为7个在途、100ms最小启动间隔、30次/12.25秒；250ms是客户端发送余量，不是DeepL官方额度。扩展仍为8个在途、30次/12秒。每批32项/合计1500个UTF-16单元不变。
- 修复闲置后新倒计时首帧复用旧时钟、短暂显示过长等待的问题。倒计时仅允许人工重试，不安排自动翻译。

Chrome/Edge入口、PDF阅读和文档转换入口保留；模型队列与其串行流式行为保留。

上述是**隔离浏览器的真实服务测试，不是用户实际Edge或操作系统前台视觉验收**。归档代理与observer经独立静态审查，未发现伪造429或按98/104等计数硬停的执行路径；仍不能反推出服务端具体规则。完整第三方包和本机profile未加入仓库。

## 回归与实际Edge阻塞

当前完整单元回归为1683/1683、69个文件；类型、仓库、文档、模块边界检查通过；Chrome/Edge和两渠道脚本构建通过，GitHub及Greasy Fork脚本浏览器回归各22/22。新增后台测量模式的20项定向测试、实际Edge本地站的11项纯离线逻辑测试通过。模拟回归不能替代真实DeepL验收。

为适配用户无法固定前台，基准工具新增显式`background-dom`模式：记录真实可见性与焦点，只测完整DOM和源身份；前台首屏/RAF指标始终为null。默认foreground模式仍要求真实可见和焦点，精确URL守卫在两种模式中均保留。没有覆写焦点/可见性API。

实际Edge本地测试站已准备，并核验C脚本与源文章字节；但在篡改猴“重新安装”页，Browser Use的URL策略拒绝访问`chrome-extension://`，只允许HTTP/HTTPS。已停止受阻操作，未切换原生窗口、原始CDP、管理器接口或其他浏览器代为安装。候选 C 的实际安装身份尚未核实，资格页及十篇队列的真实翻译启动次数均为0。

下一步需用户手动完成候选 C 的重新安装。版本号同为0.11.17不足以区分候选；恢复工作时须先核实实际执行代码，再做单独恢复资格与十页连续后台DOM测试。修复后的实际“停止后立即重试”仍需真实验证，不能将已有unit/mock取消测试写成现场成功。该阻塞解除前不将本轮标为完成、不合并发行。
