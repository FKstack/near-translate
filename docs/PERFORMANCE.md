# 0.4.0 整页翻译性能实测

测试页面：[Go at Google: Language Design in the Service of Software Engineering](https://go.dev/talks/2012/splash.article)。使用本机已安装 Edge 扩展、原有 DeepSeek API Key、`deepseek-flash` 非思考模式，发送实际公开英文正文，未读取、导出或记录 Key。

| 实际 API 测试 | 全文完成 | 首段可读 | 完成段落 | 失败 |
| --- | ---: | ---: | ---: | ---: |
| 优化前 | 115.427 秒 | 0.525 秒 | 314 / 314 | 0 |
| 0.4.0 第一次 | 3.792 秒 | 0.563 秒 | 314 / 314 | 0 |
| 0.4.0 新标签页复测 | 3.908 秒 | 0.688 秒 | 314 / 314 | 0 |

这两次全文完成时间约为原来的 1/30，均低于用户提出的 10–15 秒目标。每次重新打开原网页并新建翻译会话，没有命中扩展本地译文缓存；服务端缓存、负载和网络状态由 DeepSeek 与网络环境决定，不能据此保证所有后续请求的耗时。首段时间基本保持同一量级，主要改善的是全文吞吐量。

复测共返回 18,407 个译文字符，抽查了摘要、文章中部作用域说明及结尾总结，均为对应完整段落的中文译文。段落 id 映射与完整性由批量解码器检查；本次未做全文人工语言质量审校。代码块和图片不参与翻译，原 DOM 保留。

## 瓶颈与改动

1280 像素宽独立浏览器中的只读采样为 315 段、303 个唯一文本、54,201 个唯一英文字符，约 8,937 词，139 段少于 40 字符。实际用户浏览器因布局与可见项差异提取 314 段。提取加完整失效复验约 24 毫秒，远小于网络等待。

旧版每个标题、目录项、列表项和正文段落各发一次请求，仅 2 并发。新版将短段合并，每批最多 16 项、约 1,600 字符，最多 32 并发，减少重复首响应等待；合法 NDJSON 段落行到达即显示，不等整批完成。长段落可并行拆分并按原序重组。批次中断后保留已完成项，手动重试只发送缺失部分。

没有变更模型或 API 地址，没有缩写正文、减少翻译范围，也没有用预制译文替代 API。鉴权、余额、限流和连接错误仍会停止剩余队列。软件总活动请求上限为 64；官方接口并发说明见 [DeepSeek Rate Limit & Isolation](https://api-docs.deepseek.com/quick_start/rate_limit/)。

优化前实测时，安装目录是 0.3.0，用户浏览器的后台 manifest 仍显示 0.2.0；其文字请求协议与逐段 2 并发行为保持兼容。本次已通过扩展自身重载，并在实际运行态确认 manifest 为 0.4.0。

## 复现与证据

在本项目原安装目录及同一个 Edge profile 下，可运行：

```powershell
npm run benchmark:installed -- --label verification --reload --timeout-ms 90000
```

脚本打开用户指定的公开网页，点击真实悬浮栏，通过 DOM 状态计时，从点击到全部段落与批次完成；临时测试页在结束后移除。它不替换 fetch、不注入模拟 API，也不读取凭证存储。原始结果在 `.output/go-page-baseline.json`、`.output/go-page-optimized-32.json`、`.output/go-page-optimized-repeat.json`，发布时合并到 `artifacts/performance-go-v0.4.0.json`。

自动化另有 315 段 / 303 唯一文本 / 54,201 字符的人工合成页面，模拟每次请求 400 毫秒延迟，检查批次数量、并发上限、完整输出和早期回填。该模拟用于回归调度策略，未替代上述真实 API 测量。
