# 近译 × 沉浸式翻译：大众通用翻译专项对标

最新产品约束：近译保持免费，不建设本产品收费服务。免 API Key 的具体路线以[登录态可行性分析与小测试](NO_API_SESSION_TRANSLATION_FEASIBILITY_2026-10-21.md)为准。

调研日期：2026-10-21。近译基线：本地 0.7.0 源码及验证文档。目标用户：大众通用翻译用户。主对标产品：沉浸式翻译。三个子代理继续使用 GPT-6.1-Sol / xhigh，分别核验网页与服务体验、文档与多媒体场景、近译现有能力。

**判断：近译已经具备网页双语的基础执行能力。对照沉浸式翻译，最大差距在于大众用户能否直接开始使用、是否能方便地控制语言和翻译范围，以及遇到文档、输入框、图片或视频后能否继续完成任务。优先补齐这些体验，比继续扩展模型预设和长难句展示更符合当前定位。**

本报告中，沉浸式能力以官方资料为据；近译能力以当前源码和项目记录为据。未进行同条件安装、翻译质量、速度或费用实测，不把功能文档当成性能结论。“未发现”限定在本次仓库检索范围。P0/P1/P2 表示产品迭代顺序，不表示漏洞等级。历史测试与拟议验收目标均另行标明。

沉浸式官方日志当前列出 1.34.2 Release（2026-10-18），但明确日期是代码合并日，不能据此认定所有商店已发布同一版本；Beta、试验功能及套餐边界需单独核验。[官方更新日志](https://immersivetranslate.com/zh-Hans/docs/CHANGELOG/)

**3. 差距最值得投入的五个方面**

**第一，首个真实译文必须足够容易获得。**

沉浸式的官方上手流程直接引导用户翻译页面。近译要求用户先理解服务商、模型、API 地址和授权；设置保存以后显示“已就绪”，但还没有证明实际连接可用。[竞品上手](https://immersivetranslate.com/zh-Hans/docs/usage/)、[近译保存逻辑](../../src/entrypoints/options/main.tsx#L48)、[近译就绪状态](../../src/entrypoints/popup/main.tsx#L27)

建议普通模式只保留目标语言、翻译动作、必要权限与服务状态。默认服务需要真实可用的供应与额度方案，不能只隐藏 Key 输入框，也不能将共用服务密钥打包进扩展。高级模式保留 BYOK/Ollama，提供独立连接检测与清楚的错误修复入口。

**第二，网页控制应当成为完整的日常操作。**

默认翻译正文还是整个页面，是否显示原文，哪些站点自动翻译、哪些站点保持安静，会反复影响阅读。近译的通用块提取和动态观察是可复用基础，下一步应增加正文优先、显示模式和简单站点偏好，而不是继续让所有网站共用一种默认行为。

另有一个具体成本点：近译“恢复原文”会清空会话和缓存，重新开始会再发起翻译。建议把“临时显示原文”与“清空翻译会话”分开，让原文/双语/仅译文切换尽量复用当前结果；显式清理、换模型、改语言等场景再使结果失效。已有“不持久化原文译文”的原则可以继续保留，只调整当前页面内存中的显示行为。[清理与重新开始](../../src/page/mount.tsx#L59)

站点适配需要长期维护。沉浸式的官方更新记录持续包含字幕、布局、语言、权限和特定网站修复，这说明“支持动态网页”只是起点，不能代替代表性站点回归。[更新记录](https://immersivetranslate.com/zh-Hans/docs/CHANGELOG/)

**第三，多语言必须贯穿整个流程。**

当前不仅提示词是英译简中，网页候选文本和划词选区也有英文倾向的筛选。因此，仅增加下拉框无法完成通用化。[页面筛选](../../src/page/segments.ts#L22)、[选区筛选](../../src/selection/snapshot.ts#L55)

首批选择能实际验收的语言方向，例如中英双向及日/韩到中文作为候选；这不是对当前支持范围的声明。每种方向都检查整页、选区、输入、PDF 的输出语言，混合文本的跳过策略，以及切换语言后旧译文是否被错误复用。句法解释可保持英文专用，但应清楚标注并按需出现。

**第四，把“能接模型”提升为“用户能稳定完成任务”。**

近译已有超时、取消、错误分类、失败重试和部分成功保留，不应重做这些基础。值得补的是按服务配置的并发/请求频率、有限退避、可解释的失败恢复，以及真实服务支持矩阵。当前整页固定最多 32 路，429 会停止队列；对不同额度和本地模型，这只是统一参数，尚未证明普适。[调度](../../src/page/batches.ts#L2)、[限流停止](../../src/page/session.ts#L213)

普通用户看完成进度、剩余额度和下一步；高级诊断再看 token、并发和模型。后台自动换服务可能改变数据接收方与费用，应由预先明确的用户选择控制。沉浸式官方配置已展示按服务的限速、批量规模与超时参数，可作为能力参照，但不能据此断言其实测稳定性更高。[服务配置](https://immersivetranslate.com/zh-Hans/docs/advanced/)

**第五，按完整任务补齐输入、文档和多媒体。**

对标应验证用户能否写完一条外语回复、读完一份 PDF 或看懂一段字幕，而不是只统计菜单里是否有入口。输入翻译先做预览、替换与撤销；PDF 先做文字文档完整双语；图片先做单张或圈选；视频先做已有字幕。复杂排版、无字幕转写和多站点播放器适配会形成独立维护成本，应逐步扩展。

**4. PDF 对标必须拆成三条能力线**

| 沉浸式产品线 | 官方说明的定位与边界 | 对近译的实际含义 |
| --- | --- | --- |
| 免费 PDF | 标准文字型 PDF 双语阅读，可修正分段/译文框并保存或打印结果；扫描件不属于这一基础路径 | 这是近译应先追上的文档能力；我们现有阅读器能复用，但尚缺整页/全文翻译和结果导出 |
| PDF Pro | 覆盖扫描、公式等复杂抽取；可将多栏内容重排为单栏；Pro 入口 | 需要 OCR/结构抽取和阅读重排，不是简单扩大划词范围 |
| BabelDOC | 侧重保留排版和原译对照；快速开始仍标试验功能 | 与重排式 PDF 是不同目标；不能把 PDF Pro 的全部支持范围直接套用到它 |

上述区分依据为[官方快速开始的三类 PDF 说明](https://immersivetranslate.com/zh-Hans/docs/usage/)、[PDF 功能文档](https://immersivetranslate.com/en/docs/features/pdf/)及[免费 PDF 帮助](https://immersivetranslate.com/zh-Hans/docs/pdf-helper/)。BabelDOC 的 OCR 有单独帮助说明，不能直接套用 PDF Pro 的扫描件承诺；其免费与 Pro 额度也不同，不能统称仅 Pro 可用。[BabelDOC 帮助](https://immersivetranslate.com/zh-Hans/document/help/?active-tab=babeldoc) 额度与商业权益以当时实际产品界面为准，本文不固定引用易变的页数或价格。

近译建议按以下交付层次推进：文字 PDF 当前页双语 → 整文队列与中断恢复 → 可下载结果 → 复杂版式与扫描件。每一层分别检查双栏阅读顺序、跨页句子、数字、公式、表格和失败页。中间阶段可采用独立双语阅读视图，但应明确是否保留原版式。

“从本地选择文件”不等于“文件始终在本地处理”。沉浸式隐私政策描述了 BabelDOC 文件的临时保存和会员 PDF 向 Mathpix 抽取的处理路径；近译当前 PDF 文件与密码留在阅读器，只发送选中文本。若近译新增云端文档服务，应另行明确上传内容、处理方和保存规则。[竞品隐私政策](https://immersivetranslate.com/zh-Hans/docs/PRIVACY/)、[近译数据路径](../guides/PRIVACY.md)

**5. 图片、视频与收费边界**

图片文档标为 Beta：免费 OCR 在浏览器端，限 Chrome/Edge、英语与部分拉丁语；Pro 使用服务端 OCR，覆盖更多浏览器和语种。不能把“有免费图片翻译”写成所有图片、所有浏览器效果相同。近译可以先验证桌面 Chrome/Edge 单图/截图翻译，再扩大语言和场景。[官方图片文档](https://immersivetranslate.com/zh-Hans/docs/features/image/)

视频需要区分“已有字幕的文字翻译”和“无字幕视频的语音转写再翻译”。前者也需要播放器时间轴、跳播和字幕更新适配；后者增加音频处理、成本和等待。不能将已有字幕的站点覆盖套用到无字幕功能。第一阶段建议选择一个明确支持的平台与已有字幕类型，不立即承诺所有视频网站或所有无字幕内容。[字幕技术文档](https://immersivetranslate.com/zh-Hans/docs/features/video-subtitles/)、[现行视频入口](https://immersivetranslate.com/zh-Hans/video/)

AI Writing 已有官方功能入口，但本次没有充分核验具体改写操作与权益，故不据名称扩写为全套写作能力。近译先完成输入翻译即可形成清楚的用户收益，后续再决定是否扩展润色与风格改写。[入口证据](https://immersivetranslate.com/zh-Hans/docs/CHANGELOG/)

沉浸式已有基础免费与高级服务的组合，当前价格 FAQ 说明免费请求存在限制。近译保持免费，不照搬其收费层级；应核实用户自己的上游权益或本地能力，清楚显示限制。额度耗尽时不自动付费，不能从竞品宣传推导近译可提供无限上游用量。[官方方案](https://immersivetranslate.com/zh-Hans/pricing/)

BYOK 已确认是沉浸式支持的能力，但官方 Edge 商店与信任中心对免费/Pro 范围的文字存在差异。本报告不将“BYOK 完全免费”或“必须 Pro”作为确定结论，也不把“支持本地模型”视为近译独有优势。[官方商店](https://microsoftedge.microsoft.com/addons/detail/amkbmndfnliijdhojkpoglbnaaahippg)、[信任中心](https://immersivetranslate.com/zh-Hans/security/)、[Ollama 文档](https://immersivetranslate.com/en/docs/services/ollama/)

**6. 推荐迭代顺序与验收**

以下为拟议目标，尚未执行；顺序不代表开发工期承诺。

| 阶段 | 应交付的用户能力 | 可检查的验收条件 |
| --- | --- | --- |
| P0-A：网页日常体验 | 目标语言、当前页入口、快捷键、正文/全页、原文/双语/仅译文、本站偏好 | 对同一页面切换模式不重复翻译；偏好刷新后保持；停止后无新增自动请求；原网页交互可继续使用 |
| P0-B：大众首用与服务 | Chrome/Edge 分发与更新、无需 Key 的默认方案、必要权限引导、失败修复、配额和稳定性 | 10 位无 Key 新用户中至少 8 位在安装后 3 分钟内完成首次真实翻译；注册/授权阻断也计入失败；额度和费用提示真实 |
| P1-A：输入表达 | 多语输入翻译、预览/替换/撤销、常见输入控件适配 | 普通输入框、textarea 和代表性富文本编辑器分别验证；保留换行；可撤销；不自动发送 |
| P1-B：文字 PDF | 当前页/全文双语、进度、取消、失败页重试与导出规划 | 正常阅读顺序，失败页可定位；成功内容不重复处理；导出结果与阅读视图一致，版式限制明确 |
| P1/P2：图片与字幕 | 单图/截图翻译；一个平台的已有字幕双语 | OCR 错误与翻译错误可区分；字幕时间轴、跳播、暂停与切换视频均正确 |
| P2：增强与扩面 | 术语上下文、配置迁移、更多平台、复杂文档及可选学习功能 | 对应需求有使用证据；增强功能不增加普通翻译的必填配置 |

P0-A 与 P0-B 可并行。默认服务尚未确定时，可先用现有 BYOK 路径完成网页体验迭代，但不能据此宣称大众首用目标已实现。质量与稳定性检查贯穿所有阶段，不是最后单独补做。

**7. 下一轮应补的实测对比**

| 场景 | 两款产品执行同一任务 | 记录指标 |
| --- | --- | --- |
| 首次安装 | 新用户安装并翻译指定外语新闻 | 首译成功率、耗时、输入字段数、授权/登录阻断点 |
| 常规网页 | 新闻、电商商品页、帮助文档中读取指定信息 | 正文覆盖、导航误翻、布局破坏、查找信息所需操作 |
| 动态网页 | 论坛评论、社交动态持续加载 | 漏译、重复请求、原文变化后旧译文残留、停止是否有效 |
| 多语言 | 相同语义任务覆盖首发承诺的语言方向 | 识别错误、目标语言正确性、数字/否定/专名等关键错误 |
| 输入与文档 | 翻译回复草稿、阅读双栏和普通 PDF | 完成率、替换/撤销可靠性、阅读顺序、失败恢复 |
| 长页与异常 | 慢网络、429、断网、切换模型或语言 | 首段/全文时间、完成比例、恢复次数、已知用量与费用 |

性能比较需区分两组：默认产品路径（体现普通用户体验）；尽量相同服务与模型（观察提取、上下文、调度等差异）。不能将服务商或套餐差异全部归因于扩展实现，也不能把官方声称的支持范围当成实测通过率。

近译当前记录的 377 个单元测试、Edge 48 个模拟场景是工程基础；0.7.0 的 Chrome 回归和各服务真实调用仍有未完成部分。历史 Go 长文约 3.8/3.9 秒的结果不是与沉浸式的同条件比较；现有 15 个真实质量样例也尚未全部执行。[验证](../development/VALIDATION.md)、[性能](PERFORMANCE.md)、[质量样例](../development/QUALITY_SAMPLES.md)

**8. 近译应继续保留的基础**

保留原网页、动态内容处理、流式回填、失败段落重试、取消与迟到结果隔离、语境词义与常见义分离、译文先出且句法独立补充，都已经有实际实现和回归证据。这些应成为迭代的基础，而不是为对标重新做一套翻译核心。[当前功能与边界](../../README.md)

长难句拆解可作为按需增强；模型和 Key 配置保留在高级设置；数据流与费用说明继续保持清楚。面向大众的下一阶段目标是：用户不需要学习接口配置，就能方便地选择语言、翻译合适的内容、切换阅读方式，并在失败后继续完成任务。
