# 近译项目介绍页设计

设计日期：2026-10-25。用途：为 GitHub Pages 根入口提供项目介绍，让第一次访问的人理解近译的阅读体验、选择安装方式，并了解翻译服务与数据边界。本文记录研究、实现与本地验证；线上部署结果以发布工作流为准。

## 品牌与原创视觉

延续[近译品牌设计](../near-translate/DESIGN.md)和[扩展界面设计](../near-translate/EXTENSION_UI.md)：清新、自然、克制，围绕纸面阅读组织画面。

| 用途 | 颜色 |
| --- | --- |
| 主文字、深色区域 | 深绿 `#244c42` |
| 阅读纸面 | 暖白 `#fcfdf9` |
| 页面底色 | `#f2f5ed` |
| 主要行动、链接 | 青绿 `#087f83` |
| 品牌辅助、局部强调 | 薄荷 `#66cc9e` |

采用充足留白、清楚的中文标题、细边框和轻阴影，让图片与阅读内容承担主要视觉。移动端按阅读顺序自然排列；按钮具有明确文字与键盘焦点，内容保持可读对比度。装饰不抢占安装和功能说明。

素材沿用项目自身资产：

- 标志：[双叶 SVG 母版](../../../public/brand/near-translate.svg)。
- 阅读展示：[双语阅读截图](../../assets/readme/reader-bilingual.png)。

- 其他现有界面素材以[品牌设计目录](../near-translate/DESIGN.md)和当前产品实现为依据。

页面结构、文案与 CSS 应为本项目原创。使用预置文章、翻译或响应制作的截图，应在相邻说明中标明示例性质，不把示例结果当作真实网络性能或翻译质量保证。项目能力以[README](../../../README.md)、[安装指南](../../guides/INSTALL.md)及[隐私说明](../../guides/PRIVACY.md)为依据。

## 内容顺序

1. **首屏定位**：沿用“读外文，留在文章里。”说明网页双语、语境查词与专注阅读如何形成连续体验，以真实阅读界面展示产品。主行动是开始使用，次行动是查看阅读体验；导航保留 GitHub 入口。
2. **阅读过程**：从保留原句的双语阅读，到当前语境查词与长句理解，再到个人排版和长文阅读；讲清具体场景与操作收益。
3. **PDF 与文档**：介绍文字型 PDF 的选文翻译和本地文档工具，清楚区分网页功能与扩展版专属能力。
4. **翻译服务选择**：分别说明实验性免费 DeepL、自带模型 Key、连接已部署本机模型的方式。
5. **安装路径**：扩展版面向 Chrome／Edge，并提供 PDF 与文档工具；篡改猴版提供网页阅读与翻译。入口连到实际发行与安装说明，不填写尚未存在的商店地址。
6. **常见问题与项目参与**：服务条件、PDF 限制、隐私、更新与反馈、MIT 开源许可证和贡献入口。

推荐叙事以“读者在文章中需要什么帮助”为主，避免堆砌协议、工程实现和无法核验的社会证明。功能词可以作为导航，但正文需说明使用后的具体体验。

## 限制与隐私文案

- 免费 DeepL 标明实验性和可能限流，不承诺稳定、无限或固定速度；新增近译账号也不能作为上游额度保证。
- 模型词典和长句拆解注明模型模式及已支持的语言方向；不扩写成所有语言均有完整语法分析。
- PDF 按当前实现描述选中文字翻译；扫描 PDF 需要先有 OCR 文字层，不暗示整份 PDF 已支持自动全文翻译。
- 本地阅读与文档转换可先使用；主动翻译时，相应文字及可选上下文发送到用户选择的服务。“本地阅读”不扩张为整个浏览器零网络。
- API Key 使用本机口令加密；账号登录、密钥库解锁和第三方 API 鉴权应使用各自准确名称。
- 当前没有项目自有翻译中转、账号体系或使用遥测。介绍页不擅自加入统计脚本、虚构人数或下载量；后续如改变数据处理，须同步实际实现、界面与隐私说明。
- 演示仅展示预置内容，不在访问页面时自动发送真实文章翻译请求。

## 构建与路径约定

继续沿用[篡改猴构建脚本](../../../scripts/build-userscript.mjs)和现有 GitHub Pages 发布结构；介绍页构建到 `.output/userscript-site/` 的根入口。`/userscript/` 原有安装页、脚本、设置和指南路径保持可用，已有安装与更新地址不因介绍页改变。

预期公开入口为 `https://fkstack.github.io/near-translate/`；篡改猴安装入口仍为 `https://fkstack.github.io/near-translate/userscript/`。这些是路径设计约定，线上内容与验证结果需另行核验。

## 实现与本地验证

源文件为 [site/index.html](../../../site/index.html) 与 [site/styles.css](../../../site/styles.css)，由 [project-site.mjs](../../../scripts/lib/project-site.mjs) 将首页及本地资产写入现有 Pages 输出目录。`npm run build:site` 只重建首页；首次完整生成安装、设置与指南页面时运行 `npm run build:userscript`，另运行 `npm run build:greasyfork` 生成同步源。

页面无运行时 JavaScript、表单、外部字体或统计脚本。FAQ 使用原生 `details/summary`，提供跳到正文入口、键盘焦点与减少动态效果支持。文字强调色在保留品牌按钮色的同时适当加深，确保浅色底的小号文字可读。

`node scripts/design/verify-project-site.mjs` 使用独立 Chromium 和 loopback 静态服务检查生成结果：360／390／768／1024／1440 px 的页面宽度、图片加载、锚点、站内资源、FAQ 点击／键盘与跳到正文。截图和摘要写入忽略目录 `.output/project-site-checks/`，不会作为发行资产上传。完整构建还保留原有脚本安装、设置、指南和更新文件的验证。
