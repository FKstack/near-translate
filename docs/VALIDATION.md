## 0.1.1 修复与现场验证

用户实际使用发现点击「译」后显示网络错误。已在真实 Edge 后台复现：原生 `fetch` 被保存为对象成员再作为方法调用，导致 `WorkerGlobalScope: Illegal invocation`，请求根本没有发出，却被归类为 NETWORK。默认网络实现现已显式绑定 `globalThis`，公共契约、请求协议和权限保持不变。

新增默认 fetch 接收者回归测试，旧代码失败、修复后通过；浏览器模拟接口也改成严格检查接收者，避免箭头函数掩盖原生约束。另用 `node scripts/verify-native-fetch.mjs` 验证未替换的真实原生网络：隔离生产扩展使用无效占位凭证取得 HTTP 401 / AUTH，证明不再在发送前失败。

已对用户实际安装目录原位更新至 **0.1.1** 并通过扩展自身重新加载，保留原安装身份、Key和设置。扩展使用其内部既有Key、`deepseek-flash` 对公开单词 `JavaScript` 进行真实调用，返回「专有名词」和「一种用于网页开发的编程语言，此处指该语言本身。」。自检只传递无凭证设置与公开测试结果，没有读取或导出Key。实际调用成功只证明此样例与连接正常，15项完整质量样例仍待逐项验收。

## 测试隔离与复现

常规E2E后台fetch在隔离测试进程中替换为严格检查接收者的SSE模拟接口，并配置真实API请求阻断；该套自动化不使用真实Key、不产生DeepSeek调用费用。测试副本位于 `.output/e2e-extension`，只有该副本预先授予HTTP(S)权限以避开浏览器原生确认对话框。复制脚本断言生产manifest保持不变。现场自检另通过已安装扩展自己的Port执行一次真实公开单词请求，Key留在扩展内部。

```powershell
npm run typecheck
npm test
npm run check:boundaries
npm run build
$env:NEAR_BROWSER_CHANNEL = 'msedge'
npm run test:e2e
```

Chrome可用默认Playwright安装；如需要指定可执行文件：

```powershell
$env:NEAR_BROWSER_CHANNEL = 'chromium'
$env:NEAR_BROWSER_EXECUTABLE = '浏览器可执行文件的绝对路径'
npm run test:e2e
```

本机Playwright原缓存目录出现Windows SideBySide激活错误。将浏览器原样复制到工作区隔离目录后启动成功，EXE与manifest的SHA256保持一致；没有修改系统设置、安全策略或程序集。此问题属于测试环境，生产扩展不依赖该目录。
