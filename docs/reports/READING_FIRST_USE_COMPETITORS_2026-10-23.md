# 阅读模式竞品首次用户走查（2026-10-23）

## 结论与证据范围

本轮在独立空白 Chrome profile 中，以“第一次来，先把一篇文章调得舒服”为目标，真实访问了 Clearly Reader 与 Readwise Reader 的公开入口，并保存了浏览器截图及 DOM 观察。两个 Web App 在进入阅读器设置前均到达登录界面，因此没有完成其阅读器内的字号调整、双语、默认恢复、键盘或小屏验证。本文严格区分入口实测、官方说明和设计推论，不能把这一走查当作两款扩展安装后的完整测评，也不能据此断言它们不支持某项功能。

原计划使用 CUA 浏览器工具，但它在初始化及 reset 后均因 `windows sandbox ... setup refresh had errors` 退出。随后改用项目已具备的 Playwright 和 `.output/chrome-runtime/chrome.exe`，创建 `.output/reading-competitor-first-use/clean-profile`；未连接用户日常浏览器、未登录、未安装竞品、未付费、未修改日常设置。视口为 1365 × 900，headless 浏览器。此限制也意味着网络与自动化环境可能影响加载时间，不据此评价竞品性能。

Clearly 官网点击 Web App 的首次自动化尝试未捕获到最终导航；随后直接访问同一已观察到的 `/app` 路径，得到登录页。报告用后者作为入口结果，没有把点击等待或瞬时页面状态误判为产品缺陷。Readwise 也等待首次加载状态退出后才记录最终登录页面。

## 对首次用户有价值的优点与阻碍

### Clearly Reader

**观察到的优点：**首页首屏的 Web App 与安装入口清晰，用户不必读长篇帮助就能选择使用形态；外观与阅读这两类收益在官网中明确表达。

**观察到的阻碍：**从 Web App 路径出发，想先尝试字体舒适度的用户需要先经过登录。这个结论仅适用于本次 Web App 首次路径，不能外推到浏览器扩展本地使用。

**官方功能依据：**主题、系统字体、字号、行距、页边距都有明确说明；官网还介绍按词或按段翻译。这些是应该对齐的基础能力。来源：[Clearly Reader 官网](https://clearlyreader.com/)。

**推论：**提供无需账号的阅读样例或页内实时排版预览，能降低“还没看见效果就要先投入”的门槛。我们的阅读模式可以直接在当前正文里完成这个验证。

### Readwise Reader

**观察到的优点：**首次加载说明告诉用户当前正在获取文档；最终登录路径有明确的账号入口。

**观察到的阻碍：**本次未登录无法进入正文或尝试 Appearance。加载时长受到本地网络及隔离浏览器影响，不作性能排名。

**官方功能依据：**Appearance 使用 `Aa` 入口，集中字体、字号、行距和正文宽度；提供明暗与自动主题，支持隐藏两侧面板及快捷键。移动端和 Web 的主题选项存在区别。来源：[Readwise Appearance 文档](https://docs.readwise.io/reader/docs/faqs/appearance)。

**推论：**统一外观入口和可收起侧栏值得借鉴；“可以调很多值”仍需要用户了解哪组值适合自己，应在基础控件之前提供能看懂的场景选择。

### 简悦：仅作官方资料补充，未声称安装实测

简悦官方强调中文阅读习惯、目录与进度，支持主题、字号、灵活布局、快捷键和可编程适配。可吸收的是对中文长文、技术文章和原文定位的重视；可编程、插件式设置的发现成本是一个需要防范的设计风险，本文没有实测其具体操作耗时。来源：[简悦官网](https://simpread.pro/)。

## 对本产品方案的取舍

用户最先想解决的是“现在看起来舒服”“双语不干扰”“调坏了能回来”，不应该先学习字号单位、透明度或层叠样式。

| 用户问题 | 值得采用的方案 | 首次用户误解 / 实现约束 |
| --- | --- | --- |
| 不知道该怎么调 | 先给场景预设，再给常用字号、宽度、主题；高级项折叠 | “舒适”不应宣称适合所有人，始终允许细调 |
| 改设置后找不到刚才读到哪里 | 当前正文实时预览，并保持当前段落锚点 | 只保留滚动像素无法应对字号或行距引起的重新排版 |
| 害怕试预设覆盖自己的习惯 | 个人样式独立保存；切预设后可恢复；提供撤销 | 清楚区分“恢复本次调整前”“恢复推荐默认”“应用个人样式” |
| 双语页面太挤 | 用“原文优先 / 均衡对照 / 译文优先”命名层次，而非只给透明度滑条 | 弱化文字仍需清晰可读；不能把“隐藏原文”伪装成双语 |
| 不确定保存有没有成功 | 只在持久化成功后显示已保存；失败给可重试说明 | 控件变化不等于保存成功，不能让用户误以为下次会记住 |
| 设置挡住正文 | 桌面可收起，窄屏面板不溢出；Escape 先收设置，再考虑退出阅读 | 不要把调设置和退出阅读混成一次不可预期行为 |

优先实现“预设降低初始决策成本 + 当前正文即时试调 + 保持读点 + 可恢复个人习惯”的组合。它们来自本产品双语阅读场景的用户任务，比单纯堆更多主题更容易被感知。这里的“更出色”是待验证的设计目标；本轮证据支持这些改进方向，但不足以宣称整体全面超越竞品。

## 开发后的验收建议

1. 新用户不离开当前阅读正文即可看见预设效果；字号、行距与宽度调整时正文及时更新。
2. 在中段调整字号、宽度或译文层次后，当前段落仍在可见区。
3. 个人样式、场景预设、恢复推荐、撤销的作用清楚且互不误覆盖。
4. 保存失败不会显示“已保存”；重开阅读能恢复已成功保存的偏好。
5. 360px 与桌面窗口都能操作设置，无横向溢出；Tab 可达，Escape 可预期。
6. 没有为外观变更发起新的翻译请求，也不因切预设清空已有翻译。


## 补充：Readwise 无需登录的官方公开文章（真实访问）

另行在同一隔离浏览器中访问 [Reader 官方公开共享文章](https://readwise.io/reader/shared/01h5aq2qk5vmzkxk7kes90e7kf/)。这条路径无需账号即可阅读正文；首屏有文章标题、作者、预计时长、标注者以及返回原文链接，正文是清晰的单栏排版，直接交付“先读起来”的价值。

本轮页面的实际 DOM 按钮清单为空，截图中也没有 `Aa`、主题或字号控制。它是公开分享阅读页，不等同于完整 Reader Web App，没有把文章中介绍 Appearance 的文字误当成此分享页可用的设置。因此在“放大字号 / 切主题 / 恢复默认”任务前停止，不借助浏览器缩放伪造产品内排版操作。

补充证据：`.output/reading-competitor-first-use/shared-article.png` 与同名 `.json`。可吸收的优点是直接阅读、明确来源和预计耗时；对我们而言，应该让同一正文上既能开读也能调节，而无需先理解分享页与完整阅读器的区别。后一句是设计推论。
