# 近译阅读模式：竞品研究与可验证设计

研究日期：2026-10-22。近译基线：本地 `package.json` 的 0.7.0，以及本次只读检查的 `src/page`、popup、隐私说明。竞品事实来自当天联网读取的官方文档、产品页和官方公开源码说明；没有登录竞品账号，没有进行四款产品的同条件安装实测，也没有发起真实 DeepL 翻译请求。

**结论：近译应把本地正文阅读与现有双语翻译连接成完整流程：即时进入阅读 → 目录定位 → 原文/双语/译文切换 → 回到网页原段落。** 简悦已经有成熟的目录、进度与版式；Edge、Firefox 已有丰富的字体与辅助阅读能力。这些属于应达到的基线。近译可争取的优势是低操作成本、上下文不断裂、译文复用以及清楚的本地/联网边界，能否优于竞品要通过下面的对照任务验证。

## 1. 先明确比较对象

| 能力 | 本报告的定义 | 不能据此推出的结论 |
| --- | --- | --- |
| 网页阅读模式 | 提取已加载页面的正文，去除干扰，按阅读版式展示 | 不能保证适配所有网页、加载尚未出现的全文或绕过访问限制 |
| 原网页双语翻译 | 在网页内容附近显示译文，通常保留网站导航与交互 | 识别主要内容不等于已实现正文重排、目录或阅读位置恢复 |
| PDF/电子书阅读 | 解析文件及页码、文字层、目录等 | 能读 PDF 不等于能翻译 PDF；PDF 双栏对照也不等于网页阅读模式 |
| 聚焦/选区阅读 | 高亮或单独展示用户指定区域 | 不代表自动正文提取已成功 |

沉浸式翻译官方 FAQ 明确说明默认翻译识别网页核心内容并保留原布局与导航，整页翻译则扩大文本范围。因此其“沉浸式”首先描述跨语言阅读体验，不能直接理解成简悦式阅读器。[官方 FAQ](https://immersivetranslate.com/docs/faq/)

## 2. 官方能力证据与边界

“未核实”表示本次官方材料未充分说明该项，不表示产品没有该功能。文档页本身的目录不算阅读器为文章生成的目录；保存设置也不等于保存阅读进度。

| 维度 | 沉浸式翻译 | 简悦 SimpRead | Edge 阅读模式/沉浸式阅读器 | Firefox Reader View |
| --- | --- | --- | --- | --- |
| 正文与干扰处理 | 默认智能翻译内容区，另有整页范围；保留网页结构 [I1] | 提取标题、描述、正文及媒体；另有聚焦、手动与适配机制 [S1][S2] | 支持页面去干扰阅读，也可选中文字后打开 [E1] | 在适合的页面显示入口，移除广告等干扰 [F1] |
| 版式 | 原页内双语/译文样式；不能据此确认独立重排阅读器 [I2] | 主题、字体、大小、布局及代码/公式相关能力 [S1] | 字体、字号、列宽、主题 [E1] | 字体、字重、宽度、行距、字词间距、对齐与自定义主题 [F1] |
| 目录、进度、统计 | 此次网页功能文档未核实自动文章目录及阅读进度 | 官网明确列出目录、阅读进度、阅读统计 [S1] | 本次核心文档未核实文章目录与阅读进度 | 本次 Reader View 帮助未核实文章目录与阅读进度 |
| 双语/原文控制 | 原文、双语、仅译文；段落对照是核心能力 [I2] | 官网列划词翻译插件；不据此声称原生完整双语模式 [S1] | 阅读工具栏提供翻译；未核实逐段双语切换 [E1] | Reader View 与 Firefox Translations 分属功能；未核实原生段落双语 [F1][F3] |
| 回到上下文 | 原页内对照减少跳转；独立阅读视图的段落回跳未核实 | 聚焦保留原结构；阅读视图退出后的精确段落映射未核实 | 可退出阅读；原段落精确回跳未核实 | 可关闭阅读视图或返回；精确回跳未核实 |
| 快捷操作 | Alt+A 翻译/原文，Alt+W 整页，可修改快捷键 [I2] | 官方 README：双击 A 阅读，A S 聚焦，另有右键入口 [S2] | 支持页面用 F9；选区可右键进入 [E1] | 官方帮助列 F9 或平台对应组合键，依操作系统显示 [F1] |
| 辅助阅读 | 本次材料不足以评估屏幕阅读器、焦点与对比度 | 定制能力丰富；本次不足以评估无障碍完整性 | 朗读及视觉外观工具；旧版文档还列语法/词典等 [E1][E3] | 朗读依赖系统对应语言 TTS 信息，提供对比主题等 [F1] |
| 本地与联网 | 网页翻译内容发送给所选引擎；文件服务另有处理规则 [I3] | 官方称标注、稍后读、本地快照保存在本地；可选网盘同步 [S3] | 官方称核心阅读可离线，翻译/Copilot 需要联网 [E2] | Readability 可对 DOM 本地解析；Firefox 翻译模型在客户端运行 [F2][F3] |

### 沉浸式翻译：应学习“原译文随读随比”

段落对照与原文切换让核对语言更自然；独立文件翻译产品支持多种格式，但不能计为网页正文提取质量的证据。[文档翻译入口](https://immersivetranslate.com/zh-Hans/document/)

官方更新日志当前列 1.34.2 Release（2026-10-18），并明确日期是合并日期，商店审核有差异。报告不把该日志版本当成用户设备已安装版本。[更新日志](https://immersivetranslate.com/zh-Hans/docs/CHANGELOG/)

隐私政策更新于 2026-09-24，区分网页翻译、文件/图片和 BabelDoc，并说明使用统计及错误日志。应分别核对数据目的地，不能把“网页仅发给所选引擎”扩大成所有功能均不经过服务器。[I3]

### 简悦：应达到其长文阅读的基本完整度

目录、进度和排版不是可用于宣称超越的独有功能。其主动适配、手动框选与聚焦为提取失败提供补救路径；“自动提取失败后怎么办”应进入近译产品设计。[S1]

官方仓库区分 1.x 开源与 2.x 的闭源部分，公开旧代码不能直接代表当前完整商店产物。可参考交互与公开契约，不以旧源码推断现版全部行为。[S2]

### Edge：同时记录旧、新两套官方材料

新版官方页面使用 Reading mode，标注 Windows 10/11、macOS 以及 Edge 149+，并提醒设备、地区和版本会影响功能；旧版教育支持页仍使用 Immersive Reader。评测须记录实际浏览器版本、入口名称和可用控件，不能把旧版学习工具自动计入新版。[E2][E3]

新版阅读工具栏集成翻译、朗读与 Copilot 相关入口，说明用户期待阅读后的理解辅助；近译当前更应先完成阅读及翻译流程，再以实际需求决定是否增加摘要等入口。[E1]

### Firefox：应学习丰富且直接的可读性设置

Reader View 的自定义能力已超出简单明暗主题；近译至少应处理字体大小、行距、宽度和对比度，不应只做一张白色正文卡片。[F1]

Mozilla Readability 的输出含正文、标题、作者、方向与语言等元信息。官方提醒 `parse()` 会修改 DOM，建议传入克隆；它本身不负责安全净化，Firefox 集成另用净化与 CSP。可将其当提取器候选，但需要独立处理渲染安全、源位置映射与失败回退。[F2]

## 3. 近译现有基础与实现约束

本节是本地源码检查结论，不是本次阅读模式已完成的声明。

- `src/page/segments.ts:35` 已按唯一可见 article → 唯一可见 main → body 选择翻译范围；范围选择可复用，但翻译候选过滤不能直接充当阅读正文提取，中文正文、代码块和图片也需要展示。
- `src/page/session.ts:132`、`:151` 已有 reset 与纯文本译文缓存；`src/page/mount.tsx:99` 的恢复支持保留缓存。阅读模式显示切换应复用已有结果，避免重新翻译整个页面。
- `src/page/mount.tsx` 已拥有观察器、滚动监听与导航清理。阅读层需要明确自己的 DOM、焦点、滚动锁及监听器所有权，关闭/撤权/导航时统一释放，迟到响应不能重开界面。
- `src/entrypoints/popup/main.tsx` 的 `/reader.html` 是现有 PDF 入口。网页阅读模式应有清楚的文案，避免用户误以为两者是同一个文档处理流程。
- `docs/PRIVACY.md` 当前约定不持久化原文、译文与整页缓存，没有自有翻译中转及遥测。阅读设置可持久化；是否保存跨页阅读位置应单独决定，不应为进度条默认保存正文或浏览记录。

## 4. 可验证的差异化方案

以下是设计目标，不是竞品缺失功能或近译已获胜的结论。

| 优先级 | 用户体验 | 可验收要求 |
| --- | --- | --- |
| P0 | 点开就能读 | 已加载文章本地提取；服务未配置、离线或翻译出错时仍可阅读。进入阅读本身不启动正文翻译 |
| P0 | 原文、双语、译文一处切换 | 三态名称清楚；仅切换显示不发送请求；没有译文时提供显式翻译动作，失败仍保留原文 |
| P0 | 长文始终知道读到哪里 | 从有效标题生成分级目录，跳转与当前节高亮一致；进度独立于翻译完成百分比 |
| P0 | 随时回到网页核对 | 进入时保存原阅读点和焦点；退出回到原位置；阅读段落可映射到原节点，节点仍有效时回跳并短暂提示 |
| P0 | 技术文章可读 | 保留列表、引用、表格、代码、图注、普通链接；代码/宽表局部滚动，文章容器不横向溢出 |
| P0 | 清楚的版式与键盘路径 | 舒适默认行宽、字号、行距；亮/暖/暗主题；工具有可访问名称、可见焦点；Esc 退出，输入时不误触快捷键 |
| P0 | 提取失败能自救 | 明确“未识别到正文”，提供保留原网页或重试路径；若只展示有限内容，说明范围，不伪装为全文 |
| P1 | 中途翻译不打断阅读 | 只把译文补到对应段落；显示切换/字号变化以段落锚点维持阅读点；停止与失败后原文仍可访问 |
| P1 | 进度可信 | 百分比按当前阅读容器可滚动范围计算；到顶/到底正确；短文不出现 NaN；语言切换造成高度变化后重新测量 |
| P1 | 隐私边界可解释 | 阅读提取在本地，翻译明确使用当前服务；外链图片请求与正文外发分别记录；不默认保存内容历史 |

视觉建议：以正文为主，左侧目录、上方紧凑工具栏，长文滚动时保留必要控件；窄屏目录折叠成抽屉。原译文相邻排布，译文使用稳定的层次而非大面积高亮；仅译文模式也保留快速核对原文的动作。阅读模式入口应与“翻译网页”并列，避免用户必须先完成翻译才能进入。

## 5. 验收与对照评测

先用固定 HTML 夹具与模拟 provider 验证，不以真实服务请求测试 UI。以下是建议门槛，实际结果应写入单独测试记录。

| 维度 | 最少样本/动作 | 通过条件 |
| --- | --- | --- |
| 正文提取 | 英文新闻、中文长文、技术文档、无 article 页、多 article 页、短文、含导航广告页 | 人工标注的核心段落全部保留；明确排除的导航/广告不混入；无正文时有诚实回退 |
| 富文本 | 列表嵌套、块引、代码、行内代码、宽表、带图注图片、相对 URL | 结构和文本不丢失；相对链接可用；320/768/1440 px 视口正文不横向撑破 |
| 安全渲染 | script、事件属性、javascript URL、iframe、表单、页面注入样式 | 不执行源页脚本/处理器，不注入危险导航或交互；图片和链接只允许明确安全协议 |
| 目录与进度 | h1–h4、多处同名标题、无标题、短文、滚动到底 | 锚点唯一；顺序层级合理；定位不被工具栏遮挡；百分比有限且保持 0–100 |
| 显示与缓存 | 已有译文后三态往返 10 次，再开关阅读模式 | 切换不新增 provider 调用；译文与原段一一对应；无重复译文节点 |
| 上下文恢复 | 从文章中部进入，目录跳转后退出；原节点删除后退出 | 正常节点回到预期阅读点；节点失效时使用明确回退；原焦点尽力恢复 |
| 生命周期 | 翻译中关闭、撤权、切服务、SPA 导航、重复开关 10 次 | 无迟到回填、残留遮罩/滚动锁/监听器；原网站交互恢复 |
| 无障碍 | 全程键盘、200% 缩放、深色/高对比、reduced-motion | 可进入/操作/退出；焦点可见且不落到被遮挡原页面；不以颜色单独表达状态 |
| 性能 | 固定 5 万字符文章与硬件/浏览器，开关多轮 | 记录提取到正文可交互的中位数/P95；建议目标 P95 ≤ 500 ms；测量前不宣称已达到 |
| 隐私/网络 | 无服务、断网、模拟翻译服务、含外链图片 | 阅读不发正文请求；翻译仅在显式动作后；设置存储不含正文/译文；区别图片请求与正文上传 |

对照体验任务应在四款竞品与近译使用相同公开文章、相同浏览器/视口，记录实际版本、提取遗漏、操作步数与时间：①进入并找到第三节；②放大字号后继续读；③核对一个译文段落的原文；④回到原网页当前位置；⑤翻译失败后继续阅读。只有在这些指定样本和任务中取得证据，才能写“近译在该任务更省步骤/更快”；本报告不支持“全面超越”的宣传。
