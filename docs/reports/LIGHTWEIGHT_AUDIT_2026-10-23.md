# 0.11.0 轻量化与内存实测

## 结论

普通网页的常驻脚本内存增量较低，PDF 与文档转换已与普通网页隔离；完整离线功能仍需要较多安装资源。0.10.1 的主要可改问题是前台页面每秒查询后台、隐藏划词浮层提前创建 React 根、超长页面先完整收集再截限，以及未压缩的 PDF worker 和字体。现已修复并更新至 0.11.0。

内存优化实际约为单页新增 V8 堆的 **4.9%**；安装体积减少 **25.7%**。两者是不同指标。最明显的运行时改进是空闲状态查询归零和事件监听减少。

## 测量方法

Windows、Chrome **156.0.8078.4**，固定本地 40 节文章及两页 PDF。比较 0.10.1 与最终 0.11.0 构建，分别运行无扩展、已安装但未授网页权限、已授权启用三种情况；每种使用独立配置，重复三轮。同样的 Playwright 辅助上下文用于所有对照页面。

记录自然堆、每场景三次强制 GC 后的 V8 堆、DOM 节点、事件监听、已加载扩展脚本及独立后台 worker。表中内存为三轮中位数；扩展增量由启用页减无扩展页得到。所有测试使用自有样例，没有真实翻译请求，没有读取日常浏览器配置或 Key。

页面 V8 堆不包含全部浏览器进程、原生内存、图像、canvas、GPU 和 PDF.js 专用 worker。基线曾采集整个独立浏览器进程组的 Windows 工作集及私有提交；共享内存、额外进程和调试连接使其不能直接归因于扩展，未用这些数据计算优化比例。调试连接保持 worker 唤醒，空闲查询测试也不代表已经证明正常 worker 休眠时间。

## 前后结果

| 指标 | 0.10.1 | 0.11.0 |
| --- | ---: | ---: |
| Chrome / Edge 解压后构建 | 20,557,269 B | 15,271,984 B（减少 25.71%） |
| 逐文件 gzip 合计估计 | 10,472,778 B | 10,366,369 B |
| 普通单页新增 GC 后 V8 堆 | 1,213,956 B（约 1.16 MiB） | 1,154,248 B（约 1.10 MiB，减少 4.92%） |
| 10 页新增 GC 后 V8 堆合计 | 12,140,064 B | 11,543,860 B |
| 单页事件监听器总数 | 325 | 180 |
| 单页 DOM 节点总数 | 240 | 237 |
| 初始化后空闲约 10 秒的状态查询 | 10 次 | 0 次 |

无扩展页本身的 GC 后 V8 堆约 **1.26 MiB**，最终启用页约 **2.36 MiB**；没有网页权限的已安装模式与无扩展页一致。后台 worker 最终 GC 后 V8 堆约 **1.51 MiB**，全扩展共享一份；它在本次调试下保持唤醒。

最终打开阅读模式时，页面 GC 后 V8 堆约 **3.46 MiB**。空 PDF 阅读器页面约 **3.76 MiB**，载入两页 PDF 后约 **4.49 MiB**；这些 PDF 数字只包含阅读器页面 V8，专用 worker 和渲染缓冲另计，实际大 PDF 会更重。

连续开关阅读 20 次，关闭后 DOM 始终 **237**、监听器始终 **183**。阅读控制器首次使用后有 3 个固定监听，因此与未使用阅读前的 180 有区别。第 10 到第 20 次 GC 后堆从 4,205,488 B 到 4,259,216 B，仅增加约 **52.5 KiB**，表现为热身后趋于平台；本轮未发现阅读 DOM 或监听器逐次累积。该有限测试不构成任意网页、任意 PDF 的无泄漏证明。

逐文件 gzip 是压缩估计，并非实际 ZIP 或内存。字体原来就能被 ZIP 压缩，因此解压安装体积减少 25.7%，下载包不会同幅度变小。

## 实施内容

1. **移除空闲轮询。** 文档状态客户端改为首次读取、显式刷新、恢复可见及可信后台事件更新。冷却截止时间保存后立即广播，仅含服务类型、截止时间和检查时间；冻结标签或通知失败不阻塞翻译，通知期间的新截止时间会补发。UI 本地倒计时继续工作，时间到不自动请求翻译。
2. **划词 UI 按需挂载。** 初始只保留空宿主，首次需要按钮或卡片时才创建样式、容器和 React 根。关闭后卸载根并移除容器与样式，释放事件代理、Fiber、选区引用及 CSSOM。重开、阅读层迁移、PDF 划词及迟到消息隔离保持正常。
3. **阅读控制器延迟初始化。** 页面不再提前创建阅读控制器或读取阅读偏好；首次点击阅读、快捷键或 Popup 请求时建立同一个控制器。模块代码仍包含在内容脚本中，本轮没有声称实现整套代码的动态拆包。
4. **限制预先分配。** 段落收集最多建立 1,501 个完整快照，第 1,501 项供既有 1,500 段限额提示使用，随后立即停止遍历。单段文本保持完整。正文外普通侧栏、时钟变化不再触发全文重收；正文变化、祖先隐藏、文章根替换及译文节点移除继续检测。
5. **压缩离线资源。** 使用同版本 PDF.js 官方生产 worker，减少 965,371 B。完整字体以无损 gzip 保存，减少 4,323,380 B；解压 SHA-256、31,036 个字形和 Unicode 映射不变。仅导出 PDF 时本地流解压，保留取消、32 MiB 上限及失败不缓存。解压后的字体内存需求仍约 10.6 MB，未声称因此减少 PDF 运行内存。构建会清理旧的生成版 TTF，避免升级工作区重复打包。

翻译缓存原有 1,500 条／2 MiB 限额继续使用；阅读关闭、整页停止、PDF 与转换的 worker/task/canvas/Blob URL 清理已检查。没有增加依赖、权限、远程资源或自动翻译。

## GitHub 准备

- `.gitignore` 排除依赖、构建、实际安装目录、浏览器配置、测试报告、本地环境文件和生成的 PDF 资产。上传应使用 Git 候选文件，不直接打包整个工作目录。
- 压缩字体及来源说明放在 `third_party/fonts/`；原来只存在于忽略目录的静态许可证已迁入 `third_party/licenses/`。构建从依赖和这些源文件重建全部 **19 份许可证**，干净资产目录重建已验证。
- 新增 `npm run check:repo`：只检查跟踪文件和未忽略候选的体积、生成产物、环境文件、符号链接及常见凭证形状；不暂存、不推送、不输出匹配值。一个明确无效的公开连通性探测占位字符串具有精确例外。当前检查无待处理项；形状检查不替代发布前审阅差异。
- 当前源码与文档候选约 **14.5 MB**，最大文件为 **6.32 MB** 的完整压缩字体。原始内存报告合计约 0.9 MB 作为本次证据保留；基准脚本未来默认写入 `.output`，不持续增加仓库大小。
- 本轮没有创建仓库、提交或推送 GitHub。

```powershell

npm run build
npm run build:edge
npm run analyze:size
npm run check:repo

npm run benchmark:memory -- --runs 3 --no-process
```

## 验证与实际安装

完整单测 **1,257 项／52 文件**通过，TypeScript、依赖边界和差异检查通过。Chrome 84 项相关浏览器回归通过，最终按需样式版本另复验 27 项划词／PDF；Edge 最终版本 51 项阅读／划词／语言回归及 25 项文档转换通过。均使用隔离配置和模拟翻译服务；PDF 测试覆盖真实中文字形、文字提取、渲染、取消及下载。

用户日常 Edge 已备份后更新并重载为 **0.11.0**。原安装目录因历史更新曾有 **381 文件／27,746,263 B**；本次精确替换为最终构建 **333 文件／15,271,984 B**，全部文件哈希一致，原路径、配置与 Key 保留。实际安装只读核验 **26/26** 通过，样例标签和临时文件已清理。

剩余边界：内容脚本约 413 KiB，React 与阅读模块代码仍会随授权网页加载；单个超大段落和极深 DOM 尚无额外通用扫描预算；整页根为 body 时仍需观察全页。PDF 和导出场景的峰值取决于输入尺寸、图片分辨率与字形数量。当前改动优先处理实测开销，保留现有正文、语言覆盖与缓存行为。
